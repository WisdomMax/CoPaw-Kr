# 딩딩(DingTalk) 채널 자동 연결 (표시 브라우저)

이 스킬은 표시 브라우저를 통해 딩딩 앱 생성 및 CoPaw 채널 바인딩을 자동화하는 데 사용됩니다.

## 필수 규칙

1. 반드시 표시 브라우저 모드(`headed: true`)로 시작해야 합니다:

```json
{"action": "start", "headed": true}
```

2. 로그인 단계에서는 반드시 일시 정지해야 합니다:
   - 페이지에 로그인 화면(예: `로그인`, QR 코드 로그인, 휴대폰 번호/비밀번호 로그인 등)이 나타나면 즉시 자동 작업을 중단합니다.
   - 사용자에게 먼저 수동으로 로그인할 것을 명확히 안내하고, 사용자가 "로그인 완료/계속"이라고 답변할 때까지 기다립니다.
   - 사용자의 확인을 받기 전에는 다음 단계를 진행해서는 안 됩니다.

3. 모든 앱 설정 변경은 반드시 새 버전을 생성하고 배포해야 적용됩니다:
   - 봇 관련 정보 설정을 마친 후에는 **반드시 봇을 배포(Publish)**해야 합니다.
   - 앱 생성 또는 기존 앱 정보(이름, 설명, 아이콘, 봇 설정 등) 수 정 시 최종적으로 **반드시 "새 버전 생성 + 배포"를 수행**해야 합니다.
   - 배포가 완료되지 않은 상태에서 설정이 적용되었다고 안내해서는 안 됩니다.

## 실행 전 확인 사항 (필수 수행)

자동 클릭을 시작하기 전에 사용자에게 "설정 확인"을 요청하여 사용자 지정 가능 항목, 이미지 규격, 기본값을 명확히 알립니다. 다음과 같은 구조화된 확인 방식을 권장합니다:

1. 사용자가 다음 필드를 지정할 수 있도록 합니다:
   - 앱 이름
   - 앱 설명
   - 봇 아이콘 이미지 링크 또는 로컬 경로
   - 봇 메시지 미리보기 이미지 링크 또는 로컬 경로

2. 이미지 규격을 명확히 공지합니다 (중요):
   - 봇 아이콘: JPG/PNG만 지원, `240*240px` 이상, `1:1` 비율, `2MB` 이내, 둥근 모서리 없음.
   - 봇 메시지 미리보기 이미지: `png/jpeg/jpg` 형식, `2MB` 이내.

3. 기본값을 알립니다 (사용자가 지정하지 않을 경우 자동 적용):
   - 앱 이름: `CoPaw`
   - 앱 설명: `Your personal assistant`
   - 봇 아이콘: `https://img.alicdn.com/imgextra/i4/O1CN01M0iyHF1FVNzM9qjC0_!!6000000000492-2-tps-254-254.png`
   - 봇 메시지 미리보기 이미지: `https://img.alicdn.com/imgextra/i4/O1CN01M0iyHF1FVNzM9qjC0_!!6000000000492-2-tps-254-254.png`

4. 사용자가 아무런 값을 지정하지 않은 경우, 실행 전에 명확히 답변해야 합니다:
   - "모든 설정을 기본값(CoPaw / Your personal assistant / 기본 이미지)으로 설정하여 진행합니다."

## 이미지 업로드 전략 (링크/경로 모두 지원)

1. 사용자가 로컬 경로를 제공하면 해당 파일을 직접 업로드합니다.
2. 사용자가 이미지 링크를 제공하면 먼저 로컬 임시 파일로 다운로드한 후 업로드를 수행합니다.
3. 업로드 동작 순서:
   - 먼저 페이지의 업로드 입구를 클릭합니다 (파일 선택창 활성화).
   - 그 다음 `file_upload`를 호출하여 로컬 경로 배열(`paths_json`)을 전달합니다.
4. 업로드 시 오류가 발생하고 이미지 규격(크기, 비율, 용량, 형식) 문제로 판단될 경우:
   - 즉시 자동화를 일시 정지합니다.
   - 사용자에게 규격에 맞는 이미지를 직접 업로드하도록 안내합니다.
   - 사용자가 "업로드 완료/계속"을 확인하면 해당 단계부터 다시 진행합니다.

### 업로드 동작 팁

1. `file_upload`의 `paths_json`은 반드시 "JSON 문자열 배열"이어야 하며 이스케이프 처리에 주의하세요:

```json
{
  "action": "file_upload",
  "paths_json": "[\"xxx.png\"]",
  "frame_selector": "iframe[src*=\"/fe/app?isHideOuterFrame=true\"]"
}
```

2. 페이지가 iframe 내부에 있는 경우 `frame_selector`를 사용하는 것이 좋습니다. 그렇지 않으면 업로드 컨트롤을 찾지 못하거나 파일 선택창이 활성화되지 않을 수 있습니다.

3. 업로드 전에 반드시 대상 입구를 클릭해야 합니다. 직접 `file_upload`를 호출하면 다음과 같은 오류가 발생할 수 있습니다:
   - `No chooser. Click upload then file_upload.`

4. 봇 아이콘 영역의 일반적인 구조적 특징을 사용하여 요소를 찾을 수 있습니다:
   - `text: "* 机器人图标"` (봇 아이콘)
   - `button: "使用应用图标"` (앱 아이콘 사용)
   - `button: "avatar"` (일반적으로 내부에 `img "avatar"` 포함)

5. 스냅샷에 "사용 앱 아이콘"과 "avatar"가 동시에 나타나면 `avatar` 버튼을 우선 클릭하여 업로드를 실행한 후 `file_upload`를 수행합니다.

## 자동화 프로세스

### 1단계: 딩딩 개발자 센터 접속

1. 표시 모드로 브라우저 시작 (`headed: true`)
2. `https://open-dev.dingtalk.com/` 접속
3. `snapshot`을 호출하여 로그인 필요 여부 판단

로그인이 필요한 경우 다음과 같은 문구로 일시 정지합니다:

> 딩딩 개발자 센터 로그인이 필요합니다. 자동 작업을 일시 중지했으니, 실행된 브라우저 창에서 로그인을 마쳐주세요. 완료 후 "계속" 또는 "로그인 완료"라고 말씀해 주시면 현재 페이지에서 작업을 이어가겠습니다.

### 2단계: 기업 내부 앱 생성

사용자가 로그인을 확인하면 계속 진행합니다:

1. 생성 경로로 이동:
   - 앱 개발(应用开发) -> 기업 내부 앱(企业内部应用) -> 딩딩 앱(钉钉应用) -> 앱 생성(创建应用)
2. 앱 정보 입력 (사용자 지정값 우선, 없으면 기본값 사용):
   - 앱 이름: 기본값 `CoPaw`
   - 앱 설명: 기본값 `Your personal assistant`
3. 앱 저장 및 생성

페이지 문구나 구조가 예상과 다를 경우 `snapshot`을 다시 호출하여 시각적 텍스트 의미에 따라 요소를 다시 찾습니다.

### 3단계: 봇 능력 추가 및 배포

1. **앱 능력(应用能力)**에서 **앱 능력 추가(添加应用能力)**를 클릭하고 **봇(机器人)**을 찾아 추가합니다.
2. **봇 설정(机器人配置)** 우측의 스위치 버튼을 '켜짐' 상태로 전환합니다.
3. **봇 이름**, **봇 소개**, **봇 설명**을 입력합니다.
4. **봇 아이콘** 업로드 (사용자 지정 또는 기본 이미지):
   - 봇 아이콘 아래의 이미지 영역 클릭
   - 기본 이미지 링크: `https://img.alicdn.com/imgextra/i4/O1CN01M0iyHF1FVNzM9qjC0_!!6000000000492-2-tps-254-254.png`
   - 링크인 경우 다운로드 후 업로드
   - 규격 미달 시 사용자에게 직접 업로드 요청 후 계속 진행
5. **봇 메시지 미리보기 이미지** 업로드 (사용자 지정 또는 기본 이미지):
   - 미리보기 이미지 아래의 이미지 영역 클릭
   - 기본 이미지 링크: `https://img.alicdn.com/imgextra/i4/O1CN01M0iyHF1FVNzM9qjC0_!!6000000000492-2-tps-254-254.png`
   - 링크인 경우 다운로드 후 업로드
   - 규격 미달 시 사용자에게 직접 업로드 요청 후 계속 진행
6. 메시지 수신 모드가 `Stream 模式`(스트림 모드)로 설정되어 있는지 확인합니다.
7. **배포(发布)**를 선택합니다. 추가 확인 팝업이 뜨면 배포를 승인합니다. 주의: **반드시 봇을 배포**한 후 다음 단계로 넘어갑니다.

### 4단계: 버전 생성 및 전체 배포

1. `앱 배포(应用发布)` -> `버전 관리 및 배포(版本管理与发布)`로 이동합니다.
2. 새 버전 생성 (설정 변경 시마다 필요).
3. 버전 설명을 입력하고, 앱 표시 범위(可见范围)를 '전체 직원(全部员工)'으로 선택합니다.
4. 안내에 따라 배포를 완료합니다. 새 팝업이 나타나면 배포 확인을 선택합니다.
5. 배포 완료(发布成功) 상태를 확인한 후에만 다음 단계로 진행하거나 사용자에게 "설정 완료"를 알립니다.

### 5단계: 자격 증명(Credentials) 획득

1. `기본 정보(基础信息)` -> `자격 증명 및 기본 정보(凭证与基础信息)`로 이동합니다.
2. 사용자에게 해당 페이지에 `Client ID`(AppKey)와 `Client Secret`(AppSecret)이 있음을 알립니다. 직접 수정하지 않고 사용자가 직접 바인딩하도록 안내합니다.

## CoPaw 바인딩 방법

자격 증명을 얻은 후 사용자에게 다음 중 하나를 선택하도록 안내합니다:

1. 콘솔 프론트엔드 설정:
   - CoPaw 콘솔에서 `제어 -> 채널 -> DingTalk`으로 이동
   - `Client ID`와 `Client Secret` 입력

2. 설정 파일 직접 수정:

```json
"dingtalk": {
  "enabled": true,
  "bot_prefix": "[BOT]",
  "client_id": "YOUR_CLIENT_ID",
  "client_secret": "YOUR_CLIENT_SECRET"
}
```

경로: `~/.copaw/config.json`의 `channels.dingtalk` 섹션.

### 자격 증명 전달 규칙 (필수)

1. 에이전트는 사용자를 자격 증명 페이지로 안내하고, `Client ID`와 실제 `Client Secret`을 확인하여 보여주는 역할만 수행합니다.
2. 에이전트가 직접 콘솔 설정을 바꾸거나 `~/.copaw/config.json` 파일을 수정하지 않습니다.
3. 반드시 사용자가 위 두 가지 방법 중 하나로 직접 입력하도록 안내해야 합니다.

## 브라우저 도구 호출 모드

기본적으로 다음 순서를 따릅니다:

1. `headed: true` 옵션으로 `start`
2. `open`
3. `snapshot`
4. 필요한 경우 `click` / `type` / `select_option` / `press_key` 수행
5. 페이지 전환 시마다 `snapshot` 자주 호출
6. 완료 후 `stop`

## 안정성 및 복구 전략

- 가급적 최신 `snapshot`의 `ref`를 사용하고, 필요한 경우에만 `selector`를 사용하세요.
- 중요한 클릭이나 이동 후에는 짧은 대기(`wait_for`) 후 즉시 다시 `snapshot`을 찍으세요.
- 작업 중간에 세션이 만료되거나 재로그인 요청이 오면 반드시 다시 일시 정지하고, 사용자가 로그인한 후 해당 단계부터 재개합니다.
- 권한 문제나 관리자 승인 등으로 자동화가 막힐 경우 해당 지점을 명확히 설명하고, 사용자가 수동으로 처리한 후 다시 시작할 수 있도록 안내합니다.
